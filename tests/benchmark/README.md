# 填简社招 benchmark

首版 `2026-10-08-v1` 包含 Moka 幻方&DeepSeek、字节社招、AvePoint 三个真实页面的**局部结构复现**，以及一个完全合成的社招长表单。每个样本使用完整／缺失资料、空白／已有内容两个维度，共 **16 次实际扩展运行**。

这是一批固定输入的开发回归基准，不是线上网站成功率，也不是未经开发使用的 holdout。真实来源只读采集经过用户浏览器；没有上传简历、修改在线个人资料、接受声明或提交申请。北森追觅入口配置请求失败，保留为待补采样，不计为已覆盖网站。

## 日常运行

```sh
# 构建实际 dist 扩展并生成 JSON 报告
npm run benchmark

# 每次修改后，逐字段与已冻结 baseline 比较；出现倒退返回非零退出码
npm run benchmark:check

# 单独验证评分器
npm run test:benchmark
```

需要本机 Chrome / Chrome for Testing / Chromium。复用项目现有浏览器测试工具，可用 `JOB_APPLYMATE_BROWSER_PATH` 指定浏览器；baseline 比较要求浏览器版本一致。运行使用临时独立浏览器用户目录和合成资料，结束后清理，不会改动日常 Chrome 的扩展资料。测试页面禁止访问其他 HTTP(S) 地址。

报告默认在 `artifacts/benchmark/latest.json`（不入库）。每次报告记录源代码 commit、未提交文件列表、实际源文件哈希、dist 哈希、测试工具哈希、语料哈希、浏览器版本和运行时间。**commit 不能单独代表本次代码**，尤其工作区存在未提交修改时，应使用哈希确认版本。

首次建立或明确更新基准：

```sh
npm run benchmark -- --baseline tests/benchmark/baselines/<新版本>.json
```

不会覆盖已有 baseline；语料或评分工具发生变化时，必须审核变化并建立新版本，不能拿不同分母直接比较。不要为了让失败消失而删除字段或改写预期值。当前 baseline 会保留现有漏填和误填，比较关卡检查逐字段倒退，而不是要求所有样本满分；发现新的误填、检测丢失、原本正确的值变错，均失败。

## 数据与评分

| 文件 | 用途 |
| --- | --- |
| `manifest.json` | 版本、来源、profile、状态矩阵、限制 |
| `sources/*.json` | 仅渲染标签、控件和行为，无事实绑定和预期答案 |
| `profiles/*.json` | 合成社招资料，两个教育、两个工作记录；不含真实用户资料 |
| `gold.json` | 独立手工编写的预期值与 fill / preserve / leave-empty 策略 |
| `fixture.tsx` | React 受控表单；扫描探针只读，实际填写由 dist 扩展执行 |
| `capture-notes.json` | 只读采集证据、哪些行为简化、哪些选项是合成的 |
| `baselines/*.json` | 可审核且入库的逐字段结果 |

gold 当前标记为代理编写和审核，**没有冒充用户人工金标准**。页面不会收到 gold，表单没有语义 ID、record ID 或测试专用期望答案属性。控件使用中性的序号 ID；实际页面存在的字段名和厂商属性才保留。

两个政策假设需要与后续人工标注保持一致：合成长表单按资料数组顺序（最早到最近）分配工作记录；AvePoint 唯一的学历／毕业院校／专业组按最高学历记录标注，而原页面没有明确写“最高”。后者的结果应作为待审核政策差异分析，不能直接当作线上误填证据。开放文本“硕士／硕士研究生”通过 gold 中明确列出的等价值处理。

- **正确完成率**：DOM 和 React 业务状态同时匹配预期值／可填写字段。即使插件未发现或不支持字段，它也留在分母里。
- **发现率**：真实 DOM 扫描发现的 gold 控件／全部 gold 控件，另记额外检测。扫描使用当前源代码的 `createPageObserver` 只读探针并直接映射 DOM 节点；它与扩展隔离世界里的扫描并非同一个实例。填写与最终值检查加载实际 dist 扩展。
- **误填**：字段发生改变但最终值不正确，包括原值被覆盖、缺失月份被编造、DOM 写入但业务未接受。
- **原值保护／缺失处理**：已有内容必须原样保留；缺少资料和日期精度时保持空白。首次参加工作时间没有显式事实，不从某一段工作经历推断。
- **经历一致性**：每条记录的所有字段都正确才计为完整一致的记录；同时保留每个字段的细节。
- **耗时和待办**：记录运行耗时、扩展原始会话结果、未完成字段。耗时只供观察，目前不作为倒退门槛，也没有人工介入时间测量。

原生 select / radio 先检查真实提交编码，再映射所选标签；下拉搜索输入中的文字不会代替业务选中值。日期只允许格式等价转换（例如 `2017/6` 与 `2017-06`），不补造月份或日期。

未选择附件时，上传控件只检查不被改动；隐私协议、真实性声明、没有工作经历等复选框检查保留原状态。它们不计为可自动填写字段。提交计数必须始终为零。

## 扩充与上线前检查

新增站点时，先用浏览器只读检查真实空白表单与控件选项，再保存脱敏结构和明确的简化说明；用独立 gold 审核语义、所属记录、缺失值及原值策略。不要保存整页账户 HTML、手机号、Cookie、OTP、签名附件 URL 或厂商整套脚本。若需要增加／展开经历，先确认该操作是否会自动保存，避免修改线上账户。

本地结构复现无法证明厂商真实 React 状态、搜索接口、联动回滚或跨域 iframe 的行为。已有 `npm run test:form-fill:browser` 覆盖更细的日期、级联、撤销、回滚、iframe 控件回归。发布前再对相同线上页面做只读漂移检查；真正未见过的招聘页面应另建留出集。
