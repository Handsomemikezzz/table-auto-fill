# 固定招聘字段评测

当前基准 `2026-09-30-v2` 包含三个来源、六个状态和两份合成资料，共十二组离线输入。Moka DeepSeek 与 AvePoint 中国官网来源为本次只读浏览器采集的字段描述；飞书小鹏用例沿用已有诊断支持的结构，并补充本次简历编辑页标签采集。边界字段和已有答案状态是合成变体，不算新增独立网站。北森追觅需要登录，已用公开原生表单 AvePoint 替代作为留出来源。具体状态见 `manifest.json` 和 `sources/`。

预期答案由 Codex 整理，状态为 `draft-requires-human-review`，尚未成为用户审核过的人工金标准。初期结果用于检查评测方法和定位问题，不作为网站总体覆盖率。

## 运行

规则基线：`npm run eval:fields -- --output /tmp/field-report.json`。


评分器回归：`npm run test:site-eval`。控件执行回归继续使用 `npm run test:form-fill`，已有构建时用 `npm run test:form-fill:browser`。

## 结果范围

离线报告统计事实绑定准备情况，不能衡量 DOM 控件发现、实际选项操作和浏览器完成率。描述级规则评测无法重建 DOM 经历分组，遇到多条可用记录保持未确定；真实页面的整条经历绑定通过浏览器回归验证。浏览器独立断言检查真实业务状态；不要仅凭 `verified` 或页面显示文字判定语义正确。

金标准里的 `auto` 字段进入固定分母；`missing`、`preserve`、`manual` 分开统计。没有返回决策、丢失观察、虚构事实、重复决策、错记录和覆盖原值均能在逐字段报告中识别。资料充分但尚不支持的控件仍在自动任务分母。输入 SHA-256 记录 manifest、资料与所有样本内容，比较时必须保持一致。

## 补充与审核

先从已登录的企业申请页只读采集标签、类型、模块和选项，再脱敏写入独立版本的来源文件。采集前后保留“不写入、不上传、不提交”的行为边界；不要保存用户值、认证令牌或登录态。

每个字段审核正确含义、主体、记录和处理策略。确认后更新 annotationStatus，并冻结新的 benchmarkVersion。未读选项使用 `unread`，真实完整列表才用 `complete`。不得按当前规则输出反过来修改正确答案以提高分数。

开发来源用于规则和组件修复；AvePoint 在首轮实现后采集并用于留出评测，未据其结果补选项标签规则；缺少标签关联的原生单选交给人工。后续若按该样本修复，它应转为开发样本，并另选留出来源。不使用构造页面冒充整张网站的执行验证。人工检查时间需在固定步骤下另行记录，本次没有人工计时数据。
