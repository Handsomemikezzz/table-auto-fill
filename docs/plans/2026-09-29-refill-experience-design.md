# 补填与个人资料更新：交互设计

日期：2026-09-29  
状态：设计提案，未实施。  
用户已确认：新增个人信息默认保存到个人资料，并填入当前网页。

## 1. 目标

用户处理一项时，能马上知道三件事：这里需要自己做什么、这次操作会改变哪里、操作结果是什么。

沿用“规则先填、模型兜底”。本提案仅优化未完成项的人工处理，不增加网站规则、全页模型等待或自主提交申请。

## 2. 当前体验的问题

根据当前面板实现与截图：

- 一个字段同时出现定位、重查、输入、更正含义、选资料、保存和跳过。用户需要自己判断哪一个是主动作。
- 页面写入与资料保存混在按钮里；“只保存资料”会被归入跳过，无法准确表达资料已完善、网页尚未填写。
- 所有补充内容使用相近的文本输入，城市、日期、链接、选项都需要用户自行组织格式。
- 默认展示可编辑的信息名称，即使已经知道这是“期望城市”；高级纠错选项又列出大量无关字段和经历。
- 缺少资料与填写失败共用处理队列。可选补充看上去像必须解决的错误。
- 全局填写仍在进行时，多数人工按钮一起禁用；处理成功后当前卡片切换，用户难以确认刚才到底保存了什么。

## 3. 总体结构：先看列表，再处理一项

任务面板分为两个列表，默认只展开当前正在处理的一项。

### 网页待处理

已有答案但网页没接受、日期未确认、资料归属需要核对等，显示一个明确的下一步。

- 学校 · 安徽大学 · 下拉框尚未选中 → **去网页选择**
- 毕业日期 · 安徽大学 / 本科 · 缺少具体日期 → **补全日期**

### 可补充资料（选填）

这里没有错误色、必处理提示或逐项跳过要求。用户不展开就保持空白。

- 期望城市 → **补充**
- 作品链接 → **补充**
- 语言能力 → **补充**

分组标题提供 **一起补充**，用于集中完善个人资料。不要再用一个混杂的下拉框承担整个任务导航。

顶部只保留主要摘要，例如“网页已填写 14 项 · 2 项待处理”。个人资料保存数量单独放在资料分组，人工/自动等详细计数放入展开信息，避免挤占操作区域。

## 4. 单项编辑器：一个答案，一个主动作

从列表进入后，显示字段名、必要的经历背景、答案控件和固定的操作区。

### 4.1 补充新信息

以“期望城市”为例：

- 标题：期望城市。
- 答案：城市选择；支持实际允许的单选、多选，资料侧可以保存用户真实的多个意向城市。
- 保存位置：个人资料 → 期望城市。默认只读；识别不确定时才出现“更改”。
- 应用到：**两处都用 / 当前网页 / 个人资料**，默认“两处都用”。
- 唯一主按钮随目标变化：**保存并填入 / 填入网页 / 保存资料**。
- 次级动作：返回列表。未执行时返回会保留草稿。

“应用到”是统一的目标选择，不再同时堆放多个同等强调的执行按钮。常见流程不增加点击：输入后直接点默认的“保存并填入”；只有想改变用途时才切换目标。选择后，在按钮上方用一句短文明确本次影响，例如“新增到个人资料，并填入当前字段”。

未提供答案时不执行，也不会凭空补默认值。用户无需为了关闭面板而逐项点跳过。

### 4.2 使用已有答案修复网页

以“学校：安徽大学”为例：

- 先展示已有答案及所属教育经历，默认不显示答案编辑表单。
- 主动作由问题决定：**去网页选择**、**检查是否已填好**或 **重试填写**。
- 默认只处理网页，个人资料无需重复保存。
- 只有用户点 **修改答案**，才进入编辑器并显示应用目标。

模型选错资料时提供 **换一条资料**，先展示相关的学校/经历候选。候选不足再展开搜索，不列出整份资料里所有不相关的字段。

### 4.3 修改已有事实

- 用户主动修改一个已有答案，默认“当前网页”，避免临时回答覆盖通用资料。
- 选择保存到个人资料后，展示旧值与新值，并使用 **更新资料并填入** 或 **更新个人资料**。
- 所属记录必须明确，例如“教育经历 → 安徽大学 · 本科 → 毕业日期”，不能另建一个扁平的“毕业日期”答案。
- 仅补足已有日期的缺失精度时，仍可默认“两处都用”，但展示完整前后对照，绝不自动补 1 日。
- 未识别的新字段显示“保存为：推荐方式 [修改]”。确认名称只发生一次，不要求所有常见字段重复命名。

## 5. 按答案类型提供输入

| 内容 | 控件与提示 |
| --- | --- |
| 年龄 | 数字输入和“岁”单位；未保存时不从出生日期偷偷推算 |
| 作品链接 | URL 输入；检查格式，不为校验而打开链接 |
| 期望城市 | 城市选择，保留单选/多选要求；网站不支持的城市仍可以只保存到资料 |
| 语言能力 | 按语言与程度输入，支持补充证书/说明；不强制用户填写不需要的结构 |
| 推荐方式等网页选项 | 使用已读取的真实选项；保存的是可理解的答案，不是网站的数字编码 |
| 日期 | 年/月/日按实际要求输入；突出缺失的精度，显示原值 |
| 普通补充信息 | 简短文本；需要长回答时才使用文本域 |

如果网站选项无法读取，主动作是去网页选择，而不是要求用户重新输入已经知道的答案。

## 6. 两个结果分别反馈

任何操作都分别维护“当前网页”和“个人资料”的结果。不要只显示一个笼统的“完成”。

| 实际结果 | 显示与下一步 |
| --- | --- |
| 两处成功 | “网页：已填入”“个人资料：已保存”，提供 **下一项** |
| 资料成功，网页失败 | “资料已保存；网页还未填入”，主动作 **仅重试网页**，保留 **去网页选择** |
| 网页成功，资料失败 | “网页已填入；资料尚未保存”，主动作 **仅重试保存** |
| 两处都失败 | 保留答案，分别说明原因；允许针对单独目标重试 |
| 只保存资料成功 | “个人资料：已保存”“网页：本次未填写”，提供可选的 **填到当前网页** |
| 只填网页成功 | “网页：已填入”“个人资料：未修改”，无需再追问用户保存 |

重试只重试失败的一侧，不重复写入已成功的网页，不创建重复资料。资料冲突时展示最新值与用户新值，让用户明确选择，不能用“整个资料版本变了”拒绝不相关字段的补充。

成功后暂留结果。用户点“下一项”再切换，不自动抢走焦点或把整张卡片替换。返回列表后完成项折叠，结果仍可查看。

## 7. 集中完善个人资料

从“可补充资料 → 一起补充”进入精简表单，一次填写多个缺失项。

- 默认操作为 **保存个人资料**，页面不自动变化。
- 只保存用户实际提供的项；空白不是删除已有资料。
- 保存后显示每项结果，并提供 **将已保存项填入当前页面**。
- 批量应用前只列出当前页面中仍存在、归属明确且可处理的目标；已经有值的字段不默认覆盖。
- 个别保存或网页执行失败不影响其他项，结果按字段保留。

这个入口解决“我现在只想把资料补完整”的场景，不必反复进入网页失败卡片。

## 8. 网页中的辅助操作

点击“去网页选择”后：

1. 滚动并高亮目标控件，提示中保留正确答案。
2. 面板收成小条，例如“请选择：安徽大学”，不遮挡下拉框。
3. 用户操作完成后读回检查；无法自动确认时提供 **我已选好，检查**。
4. 不因显示了搜索词就认定选中了选项。网页状态不明确时保留“待确认”。

读回验证仍然是必要步骤，但不要让用户重复输入已经存在的事实。

## 9. 输入与异步任务的稳定性

- 草稿按字段保留：答案、应用目标、资料归属、滚动位置都不会因为切换项目或模型刷新而丢失。
- 在用户编辑期间，只暂停该字段及依赖组的自动操作；其他字段继续填写。迟到的模型结果不能覆盖用户输入。
- 保存个人资料不依赖网页控件是否存在，也不依赖模型连接。
- 停止自动填写后，仍可以补充资料或主动手动填写单项。停止只取消自动任务，不把整套人工操作锁死。
- 网页跳转或控件被替换时，保存资料仍可继续；再次填网页前重新确认目标，不复用旧节点。
- 草稿和正式个人资料分开；输入不等于保存，切换项目不等于授权写入。
- 局部加载状态只禁用会冲突的操作。错误放在对应输入或结果旁，避免顶部长期挂一段模型错误。

## 10. 显式更新与撤销

- 修改已有网页值时显示网页当前值与拟填值，使用 **替换网页内容**；不会把普通“填入”变成隐含覆盖。
- 资料更新结果旁提供“撤销这次资料更新”，与网页的“撤销本次填写”分开。
- 如果用户或其他页面已经继续修改了该值，撤销先核对当前内容，不覆盖后来的编辑。
- 所有个人资料跨网站使用；本次字段纠正和网页操作状态不成为新的“网站资料”。

## 11. 设计验收

1. 用户无需理解字段定义表、内部路径、模型协议或网站规则。
2. 已知答案的执行问题不要求重新输入答案，也不要求再次保存资料。
3. 新资料按用户确认的默认值，同时保存与填入；始终能清楚选择只做一件事。
4. 任意部分成功都能准确显示，并且只重试失败的一侧。
5. 缺资料可直接留空；已有资料覆盖有可读的前后对照。
6. 切换项目、异步刷新、网页失败后，草稿仍保留。
7. 首版先统一单项处理、结果反馈、草稿及局部可操作状态；随后加入集中补充和细化输入控件。

交互演示使用虚构样例，只用于评审操作流程；本轮未改动现有插件实现。
