# 模型主导填写：实施记录

日期：2026-09-29

## 已实现

- 新增 `ProfileSnapshot`、`FieldRegistry`、`DecisionProvider` 和 `FillSessionController` 四个边界；现有 LLM 接入统一协议。
- 整页和区域填写共用同一条主路径。所有发现的字段，包括规则未知字段，都请求模型决策；不复用旧语义缓存直接写入，也不在模型不可用时回退到规则填写。
- 模型只能引用事实、记录和真实选项 ID。程序读取实际值，检查版本、主体、记录一致性、依赖循环、选项身份和日期精度。规则别名不会否决模型选中的真实等价选项。
- 页面操作串行；每字段最多初始决策加两轮有新证据的恢复。等待模型期间的用户编辑、停止、已存在的答案和后续手动修改受到保护。
- 主页面统一协调 iframe 观察和操作，使用一个任务面板。新出现的字段需要模型决策；唯一可对应的替换节点重新观察和决策。
- 弹窗提供“填写当前页面”，区域填写放入“更多”。资料来源和附件独立选择；上传字段也由模型绑定用户本次选定的附件。
- 任务面板分别显示自动完成、辅助完成、保留原值和跳过数。日期范围整体检查；失败时提供重新检查、定位、补充事实、含义/记录确认和跳过。
- 保存事实、确认语义、记录执行经验分别处理。补充事实默认本次使用，保存是独立动作；已知字段通过定义表更新正确的资料记录。网站纠错和执行经验带来源、结构、资料及规则版本，可禁用或删除。
- `additionalFacts` 扩展新字段，支持文本、日期、信息主体、更新时间和可选有效期；纳入备份验证。不会自动上传训练数据。
- 导入简历先保存附件并生成更新草稿；用户确认所选覆盖项后才更新通用资料。资料加载不再推断学院、学习形式和学位。
- 默认不再注入“AI 生成”按钮。新会话不生成个人经历或提交申请。

## 代码入口

- `src/autofill/`：协议、快照、定义表、LLM Provider、本地约束、会话控制器及核心回归。
- `src/background/fillSessions.ts`：会话和模型请求生命周期、作用范围及学习记录。
- `src/background/fillPageBridge.ts`：主页面到各 frame 的观察和操作桥接。
- `src/content/modelLedObservation.ts`：DOM 观察和读取选项。
- `src/content/fillTaskPanel.ts`：任务摘要和分类待办。
- `src/options/ProfileImportDraft.tsx`、`AdditionalFactsSection.tsx`、`LearningRecords.tsx`：资料确认与学习记录设置。

## 后续评测和当前边界

- Laya 适配、中文任务对比、留出招聘系统样本、真实准确率与延迟/内存评测属于设计第四阶段，本轮未执行。协议已经与具体服务商分离。
- 当前只调用用户配置的一个模型地址，没有自动云端升级路径。自定义 OpenAI 兼容本地服务支持无 API Key。
- 复杂级联控件会交给网页手动选择。当前不会自动点击“新增经历”，页面跳转后需要用户再次启动。
- 会话保存在扩展后台内存中；后台重启或资料在模型请求期间变化时，要求重新开始，不恢复旧计划直接写入。
- 撤销仅恢复仍可验证为本次写入且控件支持恢复的值。文件上传、某些组件和原本未选中的单选不承诺通用撤销。
