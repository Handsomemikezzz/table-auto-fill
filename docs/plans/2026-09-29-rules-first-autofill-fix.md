# 填写回归修复：规则优先，模型兜底

## 调整原因

全量模型主导版本增加了每个模块的模型等待，每字段执行前还跨 frame 重扫整页；模型异常逃逸到会话外层后，剩余模块被一起转为待办。这导致实际使用变慢，局部故障也会中断后续填写。

按用户反馈，将当前默认策略改回规则优先。本记录取代此前设计中“所有自动绑定都必须请求模型”的要求。

## 当前行为

1. 先使用既有字段匹配和整条经历绑定规则完成整页可确定的项目，规则路径不依赖模型配置。
2. 规则只引用本次资料快照里的真实事实，仍检查记录、主体、日期精度和用户确认的纠错。
3. 模型只处理剩余未匹配或执行失败的字段。单个模块请求失败留为待办，继续处理其他模块；单次模型请求上限为 20 秒。
4. 用户点击停止仍会取消后续操作；用户输入、独立验证、附件与资料分离等保护保留。
5. 去掉每字段的跨 frame 全页重扫；执行器就地检查目标版本，复用控件发现和标识信息。末次读回检查等待从 450 ms 改为 60 ms，初次写入仍进行稳定性验证。

## 验证范围

- 单元测试共 259 项通过，新增规则优先、无模型填写、模块失败继续、纠错约束和规则失败后的模型恢复测试。
- 浏览器回归覆盖明确字段零模型请求、未配置模型仍能填写、模型只收到剩余字段、前一模块失败后后一模块继续、停止后不上传附件，以及原有控件和跨 frame 回归。
- 本地回归使用确定性模型服务。未以这些结果声称真实招聘网站的速度提升百分比或模型准确率。
