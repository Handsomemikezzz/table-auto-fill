# 跨招聘网站自动填写：抽象、兜底与覆盖率计划

日期：2026-09-28  
状态：核心引擎、适配器与本地浏览器回归已实现；真实招聘系统的跨站覆盖率尚未测量。  
目标：让同一套填写引擎适应不同招聘系统的字段语义、数据表示和交互方式，并用独立样本验证至少 80% 的自动完成率。

## 1. 目标与成功口径

主指标是“正确且被页面稳定接受的自动完成率”，不是非空输入框数量。

自动完成率 = 无需逐字段人工介入、填写正确并经验证的逻辑字段实例 / 资料充分且本次应填写的全部逻辑字段实例。

- 字段清单由独立人工标注建立，不能由插件检测结果决定分母。漏识别、不支持、映射失败、执行失败、无法验证都计未完成。
- 单选组是一个字段；拆开的年月日是一个日期字段。日期范围预先标为一个组合字段，只有整个范围正确才算完成；重复经历分别计实例。
- 初始已有值、人工补填、人工框选后完成、用户补资料分别统计；不得混入首次自动完成率。
- 同时报告全部待填字段覆盖率、资料缺失比例、按站点平均、按控件类型分布、误填率、人工介入率、P50/P95 耗时和模型调用量。
- 普通表单字段不能因为实现困难被移出分母。附件单独列能力指标，同时在全任务报告中展示；验证码、登录和最终投递属于预先声明的流程边界。
- 建议验收目标：留出招聘系统的站点平均自动完成率达到 80%，自动写入项正确率达到 99%；身份、联系方式、经历归属等关键字段出现已知误填即阻止发布。以上是目标，不是当前结果。
- “已验证”指页面可观察的实际选择、约束和稳定状态符合预期；不代表服务器已保存。测试不以实际投递申请验证成功。

## 2. 当前代码限制

以下来自静态代码审视，尚未对截图网站做现场复现：

| 位置 | 当前限制 | 架构影响 |
| --- | --- | --- |
| src/shared/types.ts 的 DetectedField | 主要表达元素、字段类型和置信度 | 缺少逻辑字段、资料记录、控件能力和验证证据 |
| src/content/formDetector.ts | 候选主要来自 input、textarea、select | 无原生输入框的 ARIA 控件可能漏检 |
| src/content/controlSemantics.ts | 选项主要是去重后的字符串数组 | 丢失同名选项身份、原始值和父级关系 |
| src/content/index.ts 与 visualRegionFill.ts | 多套发现、取值、选项和空值规则 | 不同填写入口结果不一致 |
| src/content/formFiller.ts | 多种组件行为集中在大型填写器；部分经历按字段种类计数 | 控件逻辑与语义耦合，重复经历容易错位 |
| src/utils/dropdownOption.ts | 全局同义表包含本科/学士、高中/中专等关系 | 容易把有关联的事实当作同义事实 |
| src/utils/dateValue.ts | 自动补缺失月份/日期；缺失精度时宽松判等 | 可能增加资料中没有的信息，掩盖误填 |
| src/content/index.ts 的页填统计 | 用空白字段数量减少计算部分已填数量 | 动态显隐、错误值也可能被算作成功 |
| src/content/formFiller.ts 的部分验证 | 任意单选已选、搜索文字相同、立即回读可成为成功依据 | 无法可靠排除选错和异步回滚 |

现有规则、日期函数和点击流程可以逐步迁移；不建议推倒全部用户资料结构和界面。

## 3. 核心抽象：三条独立轴

### 3.1 字段语义：这个问题在问什么

性别、学历层次、学位、入学时间、联系人电话等属于语义。语义还应包含对象和上下文：候选人或紧急联系人、哪条教育经历、哪份工作。

允许字段语义未知，不能因为识别器没有命中就把控件从后续处理和统计中删除。保留现有 FieldType 作为初期标准词表；自定义信息通过明确的资料绑定扩展，无需首期建设大型本体。

### 3.2 资料值：答案是什么、从哪里来

在现有 UserProfile 上建立运行时规范化层，保留原始值、资料路径、稳定记录 ID 和来源。类型包括文本、标识字符串、枚举、布尔、数量、部分日期、集合、层级路径和日期范围。

- 手机、证件、邮编等保持字符串，不能仅因 DOM 使用 number 就转成数字并丢失前导零。
- 日期保留年、月、日精度；“至今”表示结束状态，不能自动替换为当天。
- 数量需要单位；仅在单位关系和业务含义明确时转换。
- 布尔 false、数值 0、字符串 "0"、空字符串、未知值明确区分。
- 姓名、学校、日期等事实必须来自资料；缺失学院、教育类型、日期精度不能靠默认值补造。
- 数据本身开始时间晚于结束时间时提示资料冲突，不静默交换。

### 3.3 控件能力：页面接受什么操作

控件描述“可输入、可搜索、可展开、可选择、可多选、可滚动加载、可切换年月、可展开子级”等能力。

同一性别字段可由文本、radio、select 或自定义下拉承载；同一个下拉也可承载性别、学校和城市。控件适配器不决定业务答案。

## 4. 最小数据契约和模块边界

首期只建立四份核心数据与一套适配接口，避免过度设计。

| 契约 | 核心内容 | 负责的问题 |
| --- | --- | --- |
| FieldObservation | 字段 ID、frame/root、上下文、逻辑组、控件引用、能力、约束、当前状态、选项快照及版本 | 页面上实际有什么 |
| FactBinding | 语义、资料路径、稳定记录 ID、规范值、来源、精度/单位 | 答案取自哪里 |
| FillIntent | 目标字段、资料绑定、目标选项/日期/路径、依赖项、操作前提、期望结果 | 准备填写什么 |
| FillOutcome | 状态、失败阶段、尝试记录、回读结果、验证证据、可用下一策略 | 是否成功及下一步 |

控件适配器最小接口：

    probe       判断是否适用及支持哪些能力，不改变页面
    observe     读取实际控件状态
    discoverOptions  读取或按目标搜索候选项，返回完整性状态
    apply       执行受限填写意图，返回动作结果
    verify      读取该控件可提供的验证证据

统一验证器根据业务意图和适配器证据作最终判定；不能让适配器用宽松匹配自行宣布业务成功。恢复旧值只作为明确支持的可选能力，不能承诺所有动态组件都可无损撤销。

DOM 引用保留在 content script 内。模型只获得裁剪后的字段证据、资料候选和当前快照 ID，不接收或生成任意页面代码。

建议模块职责：

- observation：统一发现逻辑字段，合并容器、触发器、搜索输入和结果展示元素。
- binding：识别字段语义，绑定资料记录。
- values/options：按语义规范化值、解析真实候选项。
- adapters：原生、ARIA、组件家族、少量站点扩展。
- session：控制依赖、页面变动、取消、重试与串行交互。
- verification/recovery：统一结论、恢复路径和失败提示。

模块可以先是少量文件，无需逐项创建目录、类层次或通用脚本语言。

## 5. 页面观察与候选发现

### 5.1 以逻辑字段为单位

扫描原生控件、带明确 ARIA 语义的控件、可编辑区域和与表单字段关联的触发器。把一个自定义下拉的外壳、搜索框、隐藏值、弹层和已选展示视为同一个逻辑字段。

标签证据包括 label/for、aria-labelledby、aria-label、legend、autocomplete、字段容器、模块标题、邻近说明与版面关系。把这些作为证据组合，不能仅靠某个 class 或一个固定邻接关系。

所属弹层优先由 aria-controls/owns 和适配器已验证的结构关系确定；不能随意选择页面上另一个可见下拉的选项。

### 5.2 正确表示选项

选项保存 optionId、显示文字、可获得的 rawValue、禁用状态、父节点、定位证据。原始值允许未知：可以通过选择真实页面选项，让网站自己的组件完成底层编码。

选项集合需要区分未读取、加载中、部分读取、完整读取和读取失败。没有读到候选项不能直接推断网站没有该选项。虚拟列表和远程搜索通常只能得到部分集合。

同名不同值、同名不同父节点不能按文字去重。选项 ID 只在对应快照版本内有效；DOM 或上游依赖变化后重新解析。

## 6. 资料与页面选项的映射

推荐顺序：

1. 明确字段语义下的规范值和选项文字精确匹配。
2. 该字段语义内、已验证为等价的别名匹配。
3. 使用父级路径、单位、经历上下文等证据消歧。
4. 让模型在实际候选 optionId 中选择，或返回无法确定。
5. 用户确认映射，验证成功后保存限定作用域的规则。

“相关”不等于“等价”：本科与学士分别属于学历和学位；研究生不能无条件等于硕士；应届生不能无条件等于在校生。模糊文字匹配可以生成候选，不能单独成为执行或成功依据。

对性别编码的处理示例：

| 资料事实 | 当前页面选项 | 处理 |
| --- | --- | --- |
| 男 | 标签男，值 "0" | 选择该真实选项 |
| 男 | 标签男，值 "1" | 选择该真实选项 |
| 男 | 标签 Male，内部值不可见 | 通过字段内别名选择页面选项 |
| 男 | 只读到无标签 0/1 | 继续查证据；仍不明确则人工确认 |

不存在跨网站通用的 0/1 性别约定。解析到网站内部值也不意味着要直接改隐藏输入或调用网站提交接口。

## 7. 执行适配与组合字段

### 7.1 适配顺序

优先原生 HTML，其次标准 ARIA 和通用 DOM 行为，再使用组件家族适配，最后是少量范围受限的站点补充。

适配器依据实际 DOM 和行为能力选用，不仅看域名或 CSS 类名。已验证的特殊适配器可覆盖通用策略；不要在已经成功后继续尝试其余适配器。

ARIA combobox 的弹层可能是 listbox、tree、grid 或 dialog，说明“combobox”本身并不等于普通选项列表。因此需探测弹层和交互能力，再决定是否使用选择器、树或日期面板适配。依据：[W3C Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)。

首批能力覆盖文本、单选/多选、原生选择、自定义搜索选择、日期、日期范围、级联和重复经历。具体投入顺序由基线失败分布决定，不能未经测量就断言某几类能覆盖 80%。

### 7.2 重复经历先绑定整组

教育或工作块先绑定一个稳定 recordId，再填写学校、专业、职位、起止日期等字段。避免按字段出现次数分别递增索引。区分重复经历与“最高学历”“最近工作”这类摘要问题。

AI 以逻辑块获得上下文，可以一次给一组字段作绑定；不再逐字段独立猜所属经历。资料排序改变后仍按记录身份读取当前值。

### 7.3 轻量依赖调度

首期使用 groupId、recordId、dependsOn 即可：

- 省份完成后加载城市；城市完成后加载区县。
- 创建经历行后重新扫描，再绑定该行字段；重试不能重复添加经历。
- 日期范围按当前值和组件约束选择写入顺序，随后成组验证。
- 年月日拆分控件映射到一个规范日期。
- “至今/在读”开关改变结束日期控件时，按更新后的结构执行。

上游变化使下游选项和结果失效，必须重新读取并复核。页面交互串行进行，避免多个弹层争抢焦点；语义分析可以按独立块批量处理。

## 8. 验证与按原因兜底

### 8.1 统一生命周期

    发现 → 确定语义与资料 → 具备执行/验证条件 → 执行 → 验证 → 已验证

旁路状态包括等待依赖、缺资料、映射不明、交互失败、页面已变化、无法验证、能力不足、保留用户值、已取消。

写入动作成功不等于字段成功。所有入口的计数、提示和记忆保存必须消费同一份 FillOutcome。

### 8.2 验证规则

- 文本：规范值和格式正确，失焦及必要更新后保持，无新增字段错误。
- 单选/下拉：验证目标选项身份和最终选择状态；搜索框内的关键词不算已选择。
- 多选：验证目标集合；“增加”与“替换”是明确的不同操作。
- 日期：验证资料精度和目标精度，缺失日不能由日期判等函数掩盖。
- 日期范围/层级字段：检查完整组合及资料归属，不只分别检查子输入非空。
- 所有字段：写入前核对当前值与快照；用户中途修改即让出控制权。会话末复核被联动影响的字段。

React 的受控 select 由状态决定值，需要对应状态更新才能保持，因此立即修改 DOM 值并回读不能作为通用成功证明。依据：[React select 文档](https://react.dev/reference/react-dom/components/select)。

### 8.3 兜底根据失败原因路由

| 失败原因 | 下一步 |
| --- | --- |
| 资料缺失 | 提示补资料，继续其他字段 |
| 字段含义或经历归属不明 | 补读模块上下文；模型按整组判断；仍不明则请用户选择资料记录 |
| 未读到实际选项 | 展开、等待加载、按目标搜索、有限滚动后更新快照 |
| 编码含义或候选项不明 | 依据真实文字/父级消歧；受约束 AI 或人工确认 |
| 已知答案但控件不接受 | 换兼容交互适配器，不反复询问同一个答案 |
| DOM 重建或上游联动 | 重新定位与探测，再决定是否仍需填写 |
| 模型不可用或超时 | 保留已有结果，继续本地可处理字段；视觉层缺失不导致整页失败 |
| 视觉语义难判断 | 有视觉能力时采集相关区域，辅助识别；输出仍绑定可执行目标 |
| 无法操作或无法验证 | 高亮原控件，提供建议答案/复制/页面手动选择；记录为辅助处理 |

视觉是补充语义证据的一层，不能自动获得新的浏览器交互权限。不能把“看见按钮”当作“插件一定能可靠操作”。

初始预算建议：每字段最多两种不同写入策略、一次 DOM 重新定位、一次有新增证据的 AI 补判；视觉另设一次区域预算。加载和搜索设置有限时间/滚动窗口，依据 P95 数据调优，不固定睡眠后就假定成功。同一策略、目标和页面状态失败后不重复执行。

执行中关闭本次弹层、恢复本次临时搜索内容等清理需依据适配器能力；恢复失败标为待处理，避免把半完成状态交给下一个策略继续盲写。

## 9. 学习记录与缓存

分开保存三类内容：

1. 用户资料：用户明确提供的事实和当前值。
2. 字段绑定：某表单语义对应哪类资料或哪条记录。
3. 控件经验：在特定组件/表单结构下，经过验证的选项映射和操作方式。

站点规则至少限定域名/表单结构、字段语义和选项结构；结构或选项变化时重新验证。缓存记录语义和绑定，运行时读取当前简历资料，避免长期复用旧答案。切换简历、规则版本或资料版本使相关缓存失效。

只有验证成功或用户明确确认的结果可成为记忆；失败尝试和模型自报置信度不能自动升级为规则。网站数字编码不写回个人资料。用户可清除记忆。

诊断默认保留必要结构、失败阶段和证据类型，示例与测试使用脱敏资料；不为调试默认记录整份真实简历。

## 10. 扩展运行环境边界

当前扩展 content script 默认处于 isolated world。共享 DOM 不等于可通用访问网站框架的 JS 私有对象，因此现有 React 私有属性调用不应作为泛化主干。需要时只能建设能力受限、可测试的组件桥接，而不是执行模型生成的脚本。依据：[Chrome content scripts 文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

iframe 由各自可注入的 content script 扫描并报告，统一携带 frame 身份；顶层不能假设可直接遍历所有跨源 frame。页面或 frame 导航后使旧控件引用失效。

不可访问的节点、无可靠控件锚点的 canvas 或无法通过当前交互能力提交的控件进入明确的人工兜底。后续如增加执行权限或新的交互技术，单独评估，不把它们隐含为首期能力。

## 11. 跨网站验证方案

### 11.1 两层样本

控件契约样本使用原生控件、真实 React/Vue 受控组件及有代表性的组件库，覆盖异步加载、节点重建、错误状态和联动。不能只给手写 div 加组件库 class 就宣称支持该库。

真实招聘系统样本建议首批选择 8–12 个独立系统、12–20 个表单流程、约 500–1000 个业务字段实例。按系统和组件实现划分开发集与留出集，首批至少保留 3 个独立系统进行首次访问验收。规模是建议采样目标，后续按站点差异与结果稳定性扩充。

同一 ATS 换企业域名不算完全独立系统。覆盖校招/社招、中英文、企业自建/ATS、单页/多步、不同经历数量。留出组关闭站点记忆；通用能力首次成功率和学习后成功率分开报告。

### 11.2 专门检验泛化的变体

- 选项文字不变，随机改编码、交换 0/1、调整选项顺序。
- 业务语义不变，改变 DOM 层级、class、id 和 label 关联方式。
- 同一个字段在原生 select、自定义下拉、radio 间切换。
- 同一资料改变教育经历排序，增加/减少某条经历中的可见字段。
- 同名城市处于不同省份；禁用项、占位项、重复标签、肯定/否定近似文字。
- 选项延迟出现、搜索响应乱序、虚拟列表只显示部分项、弹层挂到 body。
- 搜索框有文字但未选择、失焦清空、延迟回滚、上游更改清空下游。
- 用户中途修改、取消、模型超时、节点被替换、iframe 和可访问 Shadow DOM。

语义保持不变的情况下，最终业务答案应保持一致。这组变体可直接发现对编码、顺序和选择器的依赖。

### 11.3 测试与发布

- 单元层测类型、规范化、候选解析、资料绑定和失败路由。
- 真浏览器层加载实际扩展，验证隔离环境和完整填写链路；测试页检查实际组件状态及表单数据，不能仅检查可见文本。
- 当前浏览器烟测只列 Windows 浏览器路径，且默认 npm test 和发布流程未运行该烟测；需先改为可在开发机和 CI 执行的浏览器测试，再加入发布检查。
- 真实网站验收记录页面证据、人工真值和失败阶段；被调试过的留出站点转为回归样本，下轮使用新的留出站点。
- 每层兜底报告增加了多少正确完成、增加多少耗时与模型调用，避免用成本失控的重试掩盖架构问题。

## 12. 实施阶段与交付物

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0：基线与契约 | 独立字段清单、失败分类、四份核心契约、现有指标基线 | 能解释失败发生在哪一层；分母不依赖扫描器 |
| 1：通用纵向链路 | 文本、原生选择、单选/多选；选项身份与规范值；统一执行和验证 | 编码反转/文字别名/不同控件的同语义测试通过；入口使用同一验证结论 |
| 2：动态与组合能力 | 搜索/虚拟选项、日期/范围、级联、重复经历、依赖和重新定位 | 真实受控组件、异步加载、回滚和记录归属测试通过 |
| 3：受限智能兜底 | 按块 AI 绑定、候选 ID 消歧、按需视觉、重试预算、人工接管和记忆 | 每类失败有可恢复路径；未验证结果不记忆、不计成功 |
| 4：跨站验收 | 浏览器测试接入 CI、独立系统留出评测、按失败频率补能力 | 80%/正确率目标经样本验证；报告各站点、控件类型和耗时分布 |

每阶段都跑已有回归和新增契约测试。先贯通一条可验证的链路，再扩展控件类型；不先搭建庞大框架再等待最后一次验收。

迁移保留现有资料存储和 UI 入口。快速填写、AI 扫描、框选、聚焦写入、失败补填共享观察、意图、执行和验证；入口只选择范围和允许使用的能力。快速填写可继续仅用本地规则，框选可继续优先视觉，不强迫所有入口使用相同推理策略。

新旧实现按会话/控件路由切换，不能同时写同一个字段。旧 helper 逐步封装进适配器；即便使用旧执行方法，结果仍必须经过统一验证。暂缓大型站点脚本 DSL、全自主视觉点击代理和每网站独立引擎。

## 13. 开始实现前已确定的取舍

- 优先抽象字段、值和控件能力，再补具体网站样例。
- 程序负责可验证的转换、执行和边界；模型负责语义与候选消歧。
- 泛化依靠能力组合、完整证据和失败闭环，不依靠放宽匹配条件。
- 80% 是需要测量并迭代达到的验收目标，当前不作达标承诺。
- 截图中的性别和起止时间作为回归案例，与跨网站变体一起验证，不能作为全部设计边界。

## 14. 本次实现与剩余验收

### 已接入的实现

- controlObservation / fillEngine：逻辑控件、选项身份、关联弹层、稳定验证、有限操作重试、取消与用户编辑保护；原生控件、ARIA 控件和常见组件共用执行协议。
- optionResolver / dateValue：按字段语义解析选项，拒绝数字编码猜测和歧义；保留日期精度并验证真实日历。
- datePickerAdapter / cascaderAdapter：有界日历导航、实际候选选择、明确层级路径逐级选择和完整结果验证。真实 Ant Design Select、DatePicker 和 Cascader 有浏览器用例。
- fieldBinding：教育、工作、项目按整组绑定；支持明确学历层次、已有学校/公司名称、缺失字段、嵌套日期组、独立学历摘要和稳定记录 ID。
- fieldMapping：AI 按逻辑块返回资料路径和实际选项 ID，整批检查业务语义、资料来源和经历一致性；文本与视觉入口使用同一验证规则。
- 所有表单填写入口共用执行与成功计数；失败面板展示原因和真实选项，并可定位原网页处理。异步框选、普通填写和 AI 扫描互斥。
- 学习记录的集合路径跟随稳定记录 ID，资料重排或切换后重新读取；旧索引记忆无法验证时不再复用旧答案。
- 真实浏览器回归加载构建后的扩展，通过公开消息触发填写并检查 React 状态；发布工作流已加入同一回归脚本。

### 运行检查

- npm test：既有测试与新增日期、选项、资料绑定、AI 来源验证测试。
- npm run build：TypeScript 与扩展产物构建。
- npm run test:form-fill：构建后运行本地真实 React、Ant Design 和扩展入口回归。
- npm run test:extension-smoke：既有扩展烟测，使用跨平台浏览器定位。
- npm run lint：静态检查。

浏览器用例及环境说明见 tests/form-fill/README.md。测试仅使用本地合成资料，不提交真实申请。

本次本地验证结果：TypeScript/构建通过；npm test 共 261 项通过；真实浏览器 45 项通过；既有扩展烟测通过。lint 无错误，保留仓库原有 5 条警告。已从通过浏览器回归的 dist 生成 release/job-applymate-extension.zip，并验证压缩包完整性。

### 仍需独立验收的边界

- 本地组件测试通过率不等于真实网站覆盖率；需要按第 11 节收集和标注独立招聘系统样本，才可判断是否达到 80%。
- 特殊富文本编辑器、未知日期面板、无法确定父级的级联和不透明编码会明确转人工处理。
- “至今/在读”与结束日期联动、部分拆分年月日组合及所有组件库的变体，仍需专门样本扩展；不通过补造日期提高成功率。
- 视觉框选复用统一引擎；当前没有自动升级为任意坐标点击代理。
- 原始未选择的单选组没有通用的清空操作，撤销不会伪造组件状态，也不会把未恢复的组计为撤销成功。
- 云端发布工作流已配置，是否在 CI 环境成功需由后续实际工作流运行确认。
