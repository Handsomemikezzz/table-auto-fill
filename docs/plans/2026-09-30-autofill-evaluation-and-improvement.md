# 招聘表单填写改进与固定样本评测计划

日期：2026-09-30  
状态：工程改动已实施，人工标注审核与真实模型测量待完成  
范围：国内企业官网招聘表单

目标是可靠地完成常见字段，让用户在检查申请表时顺手处理少量剩余字段，并能用同一批样本比较修改效果。沿用规则优先、模型兜底和全局个人资料的现有流程，先解决评测失真与已确认的控件问题，再缩小模型决策职责。

## 已确定的取舍

- 移除上一轮建议中的 embedding、向量数据库和 Top-K 检索建设，首期直接使用现有字段定义表与相关模块上下文。
- 不确定、缺资料、复杂开放问题和不支持的控件允许人工处理；自动化覆盖率与人工完成数分别统计。
- 继续使用用户配置的一个模型服务。不新增专用 Decision Model 部署、多模型路由、推理模型升级或模型供应商对比平台。
- 字段识别与资料取值在逻辑上分开，复用现有资料快照、事实 ID、经历绑定、执行器和验证器；不要求推倒重写所有协议。
- 个人补充信息继续全局复用；本次含义确认只作用于当前会话，不恢复按网站记忆答案或字段含义。
- 首期固定三个不同表单来源的样本，验证方法后再扩充，不以十二个网站和完整网站回放作为启动条件。

## 当前基础与已知问题

| 项目 | 当前证据 | 计划处理 |
| --- | --- | --- |
| 规则优先 | `FillSessionController` 先完成整页规则匹配，再处理剩余字段 | 保留明确字段零模型请求及无模型可填写能力 |
| 模型决策 | `LLMDecisionProvider` 同时返回含义、事实、记录、选项和动作 | 明确各步职责，先缩小输入及失败恢复范围 |
| 写入约束 | 本地校验事实存在、主体、记录、选项、版本与日期精度 | 所有自动路径继续经过同一组校验 |
| 浏览器测试计数 | 脚本依赖旧文案；当前面板还将自动与辅助完成相加显示 | 使用结构化会话结果，独立统计自动与人工完成 |
| 飞书控件 | 诊断确认 UD 树选择、多选、弹层归属、扫描及 ATSX 读回缺口 | 按组件行为补适配与回归 |
| 网站覆盖 | 当前主要是本地构造表单和确定性模型替身 | 补真实字段标注与实际结构复现样本 |

以上是初始规划阶段的代码静态检查和诊断依据；本轮实施的采样与重新验证结果见末尾实施记录及验证报告。

## 改进后的主流程

```text
DOM / ARIA 观察与逻辑字段分组
    ↓
明确规则匹配
    ├─ 命中 → 绑定当前资料中的事实和经历
    └─ 未命中且有可用资料 → 按模块请求现有模型判断含义与事实绑定
                                  └─ 不确定 / 无资料 → 留空供用户检查
    ↓
程序读取事实值并做已有格式转换
    ↓
选择控件读取真实选项并匹配
    ├─ 可以确定 → 生成控件操作
    ├─ 列表未读取 → 有限读取或搜索后再判断
    └─ 不适用 / 仍不确定 → 用户在网页选择
    ↓
本地约束检查 → 控件执行 → 独立读回与稳定性验证
    ↓
已验证 / 保留原值 / 缺资料 / 人工处理
```

含义识别只解决“这个字段是什么、属于谁、对应哪条经历”，实际值仍由程序读取已有事实。姓名、学校和日期等不交给模型自由生成。选择控件使用当前真实选项身份，保留现有模型指定等价选项的能力，不因旧别名表缺少表达就一律否决。

答案已经明确而控件操作失败时，优先保留事实绑定、读回状态和失败证据。适配器不能操作就定位给用户；只有新证据涉及字段含义或经历归属变化时，才重新做语义决策。读取到新选项时可以只重做选项判断。

## 人工检查流程

复用现有任务面板和资料助手，不增加多个模式入口或逐字段强制确认。

| 剩余情况 | 用户应看到的内容 | 处理方式 |
| --- | --- | --- |
| 已有答案但控件未完成 | 字段位置、已有资料值、简短原因 | 定位网页，选择或粘贴；可重新检查 |
| 缺少个人资料 | 网站问题及缺少的信息 | 用户直接填写；可选择保存到全局个人资料 |
| 字段或经历不确定 | 原问题及相关已有记录 | 本次确认或直接在网页填写，不反复追问 |
| 复杂开放问题 | 原问题及可参考的已保存内容 | 用户自行整理并填写 |
| 已有网页答案 | 保留已有值 | 用户检查时自行决定是否修改 |

“保存资料”和“网页填写成功”分别反馈。自动完成、人工处理后验证、保留原值、跳过和缺资料分别统计。用户未点击重新检查的直接网页补填不被自动计为已验证；人工评测表可以记录实际完成情况。

## 固定测试集

### 首批样本选择

首期目标为三个企业官网、每站两个代表性页面状态，共六个状态。每个状态运行两份固定合成资料，形成十二个基础评测组合。两份资料分别包含多条完整经历，以及缺资料、日期精度不足和已有值冲突等边界。具体字段数量以人工标注为准。

| 样本 | 选择依据 | 当前状态 |
| --- | --- | --- |
| 小鹏飞书招聘 | 已有真实结构诊断，覆盖 UD / ATSX 和起止日期 | 有诊断记录；具体申请入口及可运行样本仍需核对 |
| 一个 Moka 企业申请页 | 与飞书不同的表单实现 | 待筛选可进入申请表的具体企业与入口 |
| 一个北森或企业自建申请页 | 增加一种不同模板或组件结构 | 待筛选，并作为首批留出样本 |

这些是采样目标，不是已经采集完成的网站清单。以申请页实际可访问、字段可观察为入选条件；供应商名称只用于预分组，最终依据真实模板和组件结构区分。遇到无法进入表单的候选，先替换为同类可采集企业。

前两个来源用于开发与修复；第三个来源在首轮实现冻结后统一评测，不用于调整规则。冻结报告后如将第三个来源用于修复，它必须转为开发样本，并另选新来源承担后续留出评测。三个来源只能支持试点评估，不能据此声称国内招聘网站整体覆盖率。

### 固定内容和版本

网站入口用于采样与人工复核，回归比较使用版本固定的本地样本。每个样本保存：

- 企业、原始入口、平台与组件类别、页面状态、采样日期和样本版本。
- 脱敏后的字段观察、模块标题、上下文、真实选项及完整性状态。
- 人工标注的字段含义、主体、经历记录、应填值、允许格式和应保留或留空条件。
- 用于控件执行的可运行复现、初始状态、联动或异步行为以及独立验证条件。

首期不建设全站镜像或通用 HAR 回放框架。先保存真实字段观察，并将已确认的控件结构做成小型可运行复现；静态 DOM 与结构复现都不宣称完整保留真实网站行为。仅在某个具体失败无法复现且影响比较时，再为该样本补必要接口响应或资源。

线上采集读取结构和选项；合成资料的自动写入在隔离的本地样本中执行。线上不提交申请，也不把可能触发自动保存的真实表单当自动回归环境。登录态不随样本进入仓库；抓取结果中的候选人信息、令牌与用户答案先移除。测试页面保留合成的初始值以验证原值保护。

新增页面版本进入下一版基准，已有版本保留。修改前后对比必须使用相同版本；线上改版或页面不可达单列为环境变化。

## 评测口径

| 指标 | 定义 |
| --- | --- |
| 自动正确完成率 | 正确且稳定完成的字段 / 人工金标准中资料充分且应自动处理的字段；包含漏发现和控件不支持项 |
| 自动填写准确率 | 正确自动填写项 / 实际自动填写项；独立答案或断言判定正确性 |
| 漏识别数量 | 人工标注字段中未发现的逻辑字段数，按站报告 |
| 经历绑定错误数量 | 混入其他教育、工作或项目记录的字段和逻辑组数量 |
| 验证误报数量 | 系统报告成功，但独立验证未完成的数量 |
| 人工处理量 | 需要直接补填、选项操作或含义确认的字段数，逐项记录原因 |
| 人工检查时间 | 从自动阶段结束到人工检查完成的时间，分别记录检查与补填；仅同一人员和步骤的结果可直接比较 |
| 延迟与模型请求量 | 整页自动阶段时长、请求次数、超时数；有可靠 usage 时才计 token 和成本 |

判定“应自动处理”的范围在基准冻结时标注，修改后不能通过把失败项改成“应人工”来改善分母。缺资料、原值保护和故意要求人工判断的场景独立检查，另外报告全部逻辑字段总数和每类排除数。用户主动跳过应自动处理的字段仍计自动未完成。

无需增加模型自报 confidence、概率校准或综合打分模型。人工金标准与浏览器断言是主要依据；系统的 `verified` 状态本身不证明字段语义正确。

工程回归用确定性模型替身验证流程，真实模型评测使用同一份冻结输入及已配置模型，记录模型、提示词和参数。真实模型可重复三次观察稳定性；不将重复次数当新增独立样本。小样本报告原始计数和逐站结果，不承诺 99% 的总体统计准确率。
